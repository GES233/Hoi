# 周方案设计草案

状态：已确定产品边界，待继续讨论后进入实现

更新日期：2026-10-14

## 1. 背景

当前应用已经把以下概念分开：

- 训练方案描述一场训练准备做什么，并用最低／常规两档表达完成程度。
- 实际训练记录保存真正发生的动作、组、时长和感受。
- 周期目标按日或周汇总实际训练事实，回答“练够没有”。

现有方案底层已经支持不可变版本、多动作和多计划组，但管理界面仍以单动作快捷编辑为主。下一步希望让方案具备更大的自定义空间，并加入“周方案”，同时避免把周期目标扩展为排课或日历规则引擎。

## 2. 核心决定

### 2.1 目标保持简单

周期目标继续只对实际训练事实做聚合和比较，例如：

- 每周完成至少 3 场训练。
- 每周累计记录至少 90 分钟训练总用时。
- 每日完成至少 4 个深蹲有效组。

目标不负责指定星期几训练、不生成待办，也不判断用户是否遵守了某份周方案。

### 2.2 方案分为两层

“运动方案”作为总称，包含：

1. **单次方案（现有训练模板）**：描述一场训练中的动作、顺序、计划组及最低／常规要求。
2. **周方案（新增）**：把零到多个单次方案安排到一周中的各天。

示例：

```text
三日训练周方案
├─ 周一：推日
├─ 周三：拉日
└─ 周六：30 分钟慢跑
```

周方案引用单次方案，不重复保存动作和组定义。

### 2.3 计划与事实继续分开

- 安排了一场训练，不代表训练已经发生。
- 跳过、顺延或替换计划，不自动创建实际训练记录。
- 实际训练只有在用户开始并完成训练，或主动补记后才产生。
- 自由训练不必属于周方案，但仍正常计入周期目标。
- 周方案执行状态和周期目标结果允许不同。例如周三训练顺延至周四后，方案显示“已顺延并完成”，目标按周四的实际记录统计。

## 3. 第一版范围

第一版周方案采用固定的七天循环：

- 使用周一至周日作为周期。
- 每天可以安排零到多个单次方案。
- 没有安排的日期视为“无计划”，不视为失败，也不自动生成休息事实。
- 周方案可以设置生效日期。
- 首页根据当前日期展示当天安排。
- 可以从当天安排直接开始训练。
- 可以对某次安排执行跳过、顺延或替换。
- 可以查看本周的计划执行状态。

第一版不包含：

- “练两天休一天”等非七天滚动周期。
- 根据疲劳、历史表现或目标自动排课。
- AI 生成训练处方。
- 自动猜测一场自由训练对应哪个计划项。
- 将计划完成率合并成不透明的健康分数。

## 4. 概念关系

```text
周方案版本
    │ 安排
    ▼
单次方案版本 ──────► 计划中的一场训练
    │                       │ 用户开始／补记并明确关联
    │ 定义动作与计划组       ▼
    └──────────────────► 实际训练记录
                              │
                              ├─ 单次方案完成度：未达最低／达最低／达常规
                              └─ 周期目标：按实际事实进行日／周汇总
```

单次方案完成度、周方案执行状态和周期目标是三种不同结果：

| 结果 | 回答的问题 | 依据 |
| --- | --- | --- |
| 单次方案完成度 | 这一场是否做到最低或常规量？ | 关联的单次方案版本与实际动作、组 |
| 周方案执行状态 | 原定的这场训练如何落实？ | 计划项、跳过／顺延／替换及关联训练 |
| 周期目标结果 | 这一天或这一周累计练了多少？ | 所有符合条件的已完成训练事实 |

## 5. 用户流程

### 5.1 创建周方案

1. 在“方案”页进入“周方案”。
2. 新建周方案并填写名称。
3. 按星期展开每天的安排。
4. 从已有单次方案中添加训练，可在同一天添加多个。
5. 调整同一天内的顺序。
6. 设置生效日期并启用。

单次方案的动作与计划组仍在单次方案编辑器中维护。周方案编辑器只负责组合和排期。

### 5.2 执行当天安排

首页“今日方案”按顺序显示当天计划项。每项可以：

- 开始训练。
- 查看单次方案内容。
- 临时换用另一单次方案。
- 顺延到其他日期。
- 跳过。

当天没有安排时显示轻量的“今天没有计划训练”，仍保留自由开始和补记入口。

### 5.3 查看本周

周视图按日期展示计划项及状态，至少区分：

- 未开始。
- 已记录但未达单次方案最低量。
- 已达最低。
- 已达常规。
- 已跳过。
- 已顺延。
- 被替换。

这里展示的是计划落实情况，不取代首页现有的周期目标进度。

## 6. 版本与历史语义

现有单次方案使用不可变版本；周方案沿用相同原则：

- 编辑已启用的周方案时创建新版本，不覆盖旧版本。
- 周方案版本引用精确的单次方案版本。
- 已发生的训练保留当时的周方案项和单次方案版本关联。
- 修改单次方案后，既有周方案不会静默改写；更新周安排时应明确选择是否采用单次方案的新版本。
- 归档周方案或单次方案不删除历史训练及历史排期。

这保证同一条历史记录不会因后续编辑而改变解释。

## 7. 建议数据模型

以下是概念字段，具体 Drift 定义在实现前确认：

```text
weekly_plans
  id
  name
  archived_at?
  created_at

weekly_plan_versions
  id
  weekly_plan_id
  version_number
  note?
  created_at

weekly_plan_items
  id
  weekly_plan_version_id
  weekday                 1..7，周一为 1
  sort_order
  template_version_id     引用精确的单次方案版本

weekly_plan_activations
  id
  weekly_plan_version_id
  effective_from_date
  effective_until_date?

weekly_plan_overrides
  id
  weekly_plan_item_id
  scheduled_date
  action                   skipped / moved / replaced
  moved_to_date?
  replacement_template_version_id?
  note?
```

实际训练还需要保存可空的排期关联。可以给 `workouts` 增加关联字段，也可以使用独立关联表；实现时应选择能明确表达以下信息的最小结构：

- 训练落实的是哪个周方案版本和计划项。
- 原计划日期是什么。
- 实际训练日期是什么。
- 一项计划最多由哪场训练落实。

不使用动作名称或日期相近程度自动猜测关联。

## 8. 判定原则

### 8.1 计划项完成

计划项只有在关联的实际训练完成后才进入已记录状态。之后复用现有单次方案评估结果，区分未达最低、达最低和达常规。

仅点击“跳过”或“顺延”不会生成训练次数、时长或组数。

### 8.2 自由训练

自由训练始终允许存在：

- 可以不关联任何计划项。
- 正常出现在训练记录中。
- 正常参与周期目标评估。
- 不自动填补名称相似或同一天的周方案项。

如需让自由训练落实某个计划项，应由用户明确关联。

### 8.3 顺延与跨周

周方案按原计划日期记录执行状态，实际训练事实按真正发生的日期统计。跨周顺延时，两类展示可能自然不同：

- 原周的计划项显示顺延。
- 新日期显示实际完成的训练。
- 周期目标按照实际训练日期所属周期计算。

不为了让计划表看起来完整而篡改训练日期。

## 9. 与现有界面的衔接

### 方案页

建议提供“单次方案”和“周方案”两个视图：

- 单次方案继续管理动作、计划组和最低／常规量。
- 周方案负责按星期组合单次方案和管理启用版本。

在实现周方案之前，应先补齐现有多动作单次方案的可视化编排器，否则周方案只能组合当前的单动作快捷模板。

### 首页

首页保持三块信息边界：

1. 今日方案：今天原定做什么，以及如何开始或调整。
2. 今日实际记录：今天真正做了什么。
3. 周期目标：当前日／周累计值是否达到目标。

### 目标页

目标页不增加星期排期、顺延、跳过或模板选择控件。它继续只编辑统计周期、指标、过滤条件、比较方式和目标值。

## 10. 实现顺序建议

1. 完成多动作单次方案编排器。
2. 新增周方案、版本、计划项和激活期的数据层及迁移。
3. 实现周方案编辑器和版本更新流程。
4. 在首页接入当天计划项及从计划项开始训练。
5. 增加跳过、顺延、替换及明确关联自由训练。
6. 增加本周计划执行视图和完整测试。

每一步都应保留自由训练、补记、现有模板版本和周期目标的既有行为。

## 11. 待讨论问题

以下问题尚未最终决定：

1. 同一日期是否只允许一份周方案生效。初步建议只允许一份，避免首页出现互相冲突的安排。
2. 编辑单次方案后，启用中的周方案是否提示升级引用版本。初步建议提示但不自动升级。
3. 顺延后，原日期和新日期分别如何呈现，才能清楚但不过度制造待办压力。
4. 是否需要“本周临时加练”作为周方案项，还是直接使用自由训练已经足够。
5. 周方案是否需要结束日期，还是由下一次启用新方案自动结束旧方案。
6. 计划项是否允许只填写文字备注而不引用单次方案。第一版初步建议不允许，避免形成第二套模板结构。

这些问题不影响“目标保持简单、周方案负责排期、实际记录作为事实来源”的总体边界。

## 12. 第一版验收场景

### 场景一：正常执行

启用“周一推、周三拉、周六跑”的周方案。周一从首页启动“推日”并完成最低量：

- 周一计划项显示已达最低。
- 实际训练记录正常保存。
- 周期目标按实际训练事实增加次数、时长或组数。

### 场景二：自由训练

周二没有安排，用户直接完成一场自由训练：

- 周方案不凭空新增或完成计划项。
- 实际训练正常记录。
- 周期目标正常累计该训练。

### 场景三：顺延

周三将“拉日”顺延到周四，并在周四完成：

- 周三计划项显示已顺延。
- 周四可从顺延项开始训练。
- 实际训练日期为周四。
- 周目标按周四事实统计。

### 场景四：方案改版

启用期间修改“推日”的动作或计划组：

- 历史训练继续引用旧的单次方案版本。
- 当前周方案不会静默改写。
- 用户明确更新周方案后生成新的周方案版本。

### 场景五：跳过不造假

用户跳过周六跑步：

- 周方案项显示已跳过。
- 不生成实际训练。
- 不增加周期目标中的训练次数或时长。
